The training · a choice

"Can we fine-tune a 7B model without a $40,000 cluster?"

The naive path:

  • Vanilla Hugging Face transformers
  • 4× A100 cluster on AWS
  • ~$1,200 per epoch
  • Multi-GPU configs that break in non-obvious ways

The Unsloth path:

  • Same model, 4-bit base + LoRA adapter
  • One L40S, $1.80/hour
  • 2× faster, 40% less memory
  • Output is 160 MB, not 14 GB

The wall · what almost killed it

Three bugs that cost us a full day

Bug 1 · Lazy loading.
We loaded models inside @spaces.GPU. Each query burned 60 seconds of quota just on from_pretrained. Fix: load at module level. Saved 50 seconds per query.
Bug 2 · ZeroGPU saw us as anonymous.
Even logged in, our quota was 2 minutes/day. The fix lived in a forum post: bump Gradio to 5.12. Earlier versions tracked users by IP.
Bug 3 · LoRA dim mismatch.
AutoModelForCausalLM auto-detected our adapter and tried to apply r=16 onto a base scaffolded for r=8. Fix: load via PeftModel.from_pretrained(base, adapter) explicitly.
Each one looks obvious in hindsight. Each one took hours of log-reading and forum-archaeology. This is what shipping looks like.
The wall16

Engineering · what stuck

Four lessons we'd carry to any LLM project

ZeroGPU pattern. Load on cuda at module level. Lazy is wrong. The docs whisper this; we learned it loud.
PEFT explicit. Always PeftModel.from_pretrained(base, adapter). Auto-detect is a trap.
DuckDB > SQLite. Native CSV/JSON/Parquet ingestion, ANSI SQL, 10× faster on analytics. The schema extractor is half the size.
Self-correction loop. If SQL fails, retry up to 3× with the error fed back. Took accuracy from ~80% to ~95%. Free.
